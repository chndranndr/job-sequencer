## Cross-cutting observations

- `getUsageInfo()` returned null on BOTH live runs, confirming fixture H in the wild: the
  adapter must not read null as "0 credits". For BYOK metering the source of truth is
  per-assistant `usage.billable`/`credits` + `result.modelUsage`.
- `system/init.model` reports the catalog entry's displayName, not its value. The adapter
  must map value <-> displayName via the catalog, never string-match the init frame.

  1 source=user (the owner's custom model). Only the user entry is BYOK.
